### 2-a. `CONFIG_ORDER` は v4.6.19 で修正済み

`Config.js` の `var CONFIG_ORDER`（258行目付近）が、
`var RESERVE_COUNT_KEY`（318行目付近）より**先に**評価されている。

```
node -e "var A = ['a', X, 'b']; var X = 'x'; console.log(JSON.stringify(A));"
```

`orderConfigRows()` は一致しない要素を `continue` で読み飛ばすので、他の行の並びは壊れない。

`var RESERVE_COUNT_KEY = '予備の枠数(1日あたり)';` の宣言を
`var CONFIG_ORDER = [` より前へ移した。回帰テストも追加済み。

## 6. 守ってほしい約束

作り直しの過程で決めたこと。**緩めるとテストの意味が無くなる。**

1. **モックを緩めない。** `gasmock.js` は実機の制約をわざと再現している
   （範囲外・行数0・非表示シートのアクティブ化・`setValues` の寸法違いは例外、
   キャッシュの有効期限も見る、背景色も本当に覚える）。
   緩めたくなったら、まず実機がどうなのかを確認すること。
2. **`seedSchool()` に近道を作らない。** プロジェクト自身の
   `setupSystem()` と `syncClasses()` を通している。専用の下ごしらえを足すと、
   セットアップ側が壊れてもテストが通ってしまう。
3. **新しいスイートを足したら、わざと壊して落ちることを1回は確かめる。**
   手順は [test/README.md](test/README.md) の「テスト自身の確認」にある。
   「通った」だけでは、そのテストが噛んでいるか分からない。
4. **`test/` を必ずコミットする。** 一度これで全部失っている。
5. **枠の中身は `m.slotValue()` で読む。** `m.slotRow(...).v[...]` と直接書くと、
   枠が消えた瞬間に例外で止まり、何を期待していたのか分からなくなる。
