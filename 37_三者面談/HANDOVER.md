### v4.6.8（2026-09-03）Androidで読めないQRコードを修正

- QR規格の「形式情報」15ビットが、縦・横とも規格と異なる順番で配置されていた。
  iPadの読み取りでは通る場合があったが、Androidで広く使われるZXing系では復号できなかった。
- `QrCode.js` の `qrApplyFormat_()` をJIS X 0510 / ISO/IEC 18004の配置順に修正。
- 形式情報の誤りを回避するために入っていた「マスク2を使わない」特例も削除。
  これにより規格どおり8種類から最適なマスクを選ぶ。
- 2つの本番候補URL、8種類すべてのマスク（計16パターン）を標準QRライブラリと照合し、不一致0マスを確認。
- 実際に選ばれるQRをZXingで復号し、2URLとも元のURLへ完全一致することを確認。
- 変更ファイル: `Config.js` `QrCode.js`

もともと1学年4クラス用だったシステムを、**学校全体（17クラス・400名）で使える**ようにしている途中。
まだ実運用は開始していない。

**デプロイの設定はここでなければならない。**

- 次のユーザーとして実行: **自分**（アクセスしているユーザー にすると、保護者の権限で

練習用スクリプトには古いデプロイが複数残っている。`ScriptApp.getService().getUrl()` はその中から
意図しないURLを返すことがあるため、案内プリントは「設定」シートに明示したURLだけを使う。
v4.6.1 以降は、URLが空欄・不正・到達不能ならプリント作成を止める。

**`clasp deploy` は使えない。** 実行すると
`Only users in the same domain as the script owner may deploy this script.` で拒否される
（clasp のログイン先とスクリプト所有者のドメインが違う）。`clasp push` は通る。
**再デプロイは Apps Script エディタから手作業で行う必要がある。**

**運用前に足した4件**（2026-08-22 push 済み・v4.4.0）

1. **受付開始前の自動点検** — `受付を開始する` が、押した時点で `checkData()` を走らせ、
   さらに **保護者用URLに実際にアクセスして200が返るか**を確かめる（`parentUrlReachability_`）。
   `UrlFetchApp` はブラウザのログイン情報を持たないので、保護者と同じ条件で試せる。
   302/401/403 なら「ログインを求められます」として止める。デプロイ設定の間違いはここで出る。
   エラーがあっても最終的には続行を選べる（止めるのではなく、気づかせる）。
2. **受付期間中の自動バックアップ** — `準備・メンテナンス ▸ 📦 毎日の自動バックアップを設定する`。
   毎日2時に走り、**公開中かつ締切前のときだけ**バックアップを取る。停止中・締切後は素通りするので
   ファイルは増え続けない。実行すると `予約ログ` に「自動バックアップ」として残る。
3. **当日の受付一覧（全校・時間順）** — `📄 印刷用PDFを作る` に追加。日付 → 時間 → クラスの順で、
   来校する家庭だけを並べる。受付本部の1枚用。クラス別の予約表は担任の手元用なので別物。
4. **保護者の完了画面に控えの取り方** — 「この画面のスクリーンショットを撮っておくと確実です」。
   メールを集めない方針なので、予約コードを控え損ねると保護者は自力で確認できない。
   1人予約・きょうだい予約の両方の完了画面に入れた。

**4は `index.html` なので再デプロイが必要だった。2026-08-23 のバージョン20で配信を確認済み。**

**再デプロイは反映まで数分かかることがある。** 実際、デプロイ直後に配信ページを取得しても
古い内容のままで、しばらく後に取り直したら新しくなっていた（60407→61306バイト）。
「反映されない」と判断する前に、数分おいてもう一度確かめること。

- 面談日は全学年で同じ日
