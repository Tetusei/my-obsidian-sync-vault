### v4.6.15（2026-09-03）表への手入力は「全部だめ」に統一した

v4.6.14 では、予備の行の記入欄（L〜N列）だけ手入力を許していた。
だが**「ここはよくて、ここはだめ」は覚えられない。** 手引きを読まない担任にとっては、
例外があること自体が穴になる。「作り直される表には書かない、手で入れるのは名簿だけ」
に統一した。

- **保護の範囲を広げた。** 予約表_〇組は **C〜F列**と**I〜P列**（右の表まるごと。予備の行も含む）。
  全体ビューはこれまでどおりシートごと。手で入れてよいのは **A・B列の名簿だけ**になった。
- **`captureReserveEntries_()` を削除した。** 予備の行の手入力を枠マスタへ取り込む処理。
  これがある限り「予備だけは書ける」が残ってしまう。あわせて、v4.6.13 で足した
  `syncReserveRowInClassSheet_()`（取り込み処理に消されないための書き写し）も不要になったので削除。
  副産物として、5分おきの更新から**クラス数ぶんのシート読み取りが丸ごと消えた**。
- `onEdit` の警告から、予備の行の除外をなくした。予約表のどこに書いても同じ警告が出る。
- **予備の枠の入り口は2つだけになった。**
  担任用の管理画面の黄色いセルか、予約表でその行を選んでメニュー
  「選んだ行を操作 ▸ この枠に生徒を入れる」。
- そのため、**小窓に「この枠を空にする」を足した。** これまで予備を外すのは
  「黄色い行の文字を消す」しか無かったので、直接書けなくすると外せなくなってしまう。
  小窓はいま入っている生徒も表示し、プルダウンで最初から選んだ状態にする。
- 「予約表_〇組に氏名を書いて使う」と書いていた案内文（設定シートの説明・管理画面の凡例・
  エラーメッセージ）を、すべて新しい入り口に直した。
- 変更ファイル: `Config.js` `Slots.js` `Admin.js` `Setup.js` `assign.html` `admin.html`
- **再デプロイが要る。** `admin.html` を変えたため（担任用の管理画面の凡例）。
  シート側の動きは push だけで反映される。

### v4.6.14（2026-09-03）手入力が黙って消えないようにした

手引きを読まず、感覚だけでシートを操作する担任は必ずいる。
自動で作り直される場所に手で書くと、これまでは15秒のトーストが出るだけで、
見落とせば誰にも伝わらないまま消えていた。**しかもその時間は保護者の画面では
空きのままなので、担任は「入れたつもり」、保護者は別の家庭が予約できる状態になる。**
当日まで誰も気づかない。二段構えで塞いだ。

**1. 書き込む瞬間に止める（保護：警告のみ）**

- `ensureEditGuards_()`（`Config.js`）で、Googleスプレッドシートの「保護」を
  **警告のみ**で掛ける。書き込もうとした時点でGoogleの確認が出る。
  警告のみなので［OK］を押せばそのまま書ける。作業は止まらない。
- 掛ける場所は「予約表_〇組」の **C〜F列**（左の予約状況）、**I〜K列**（日付・時間・状態）、
  **O〜P列**（予約コード・枠ID）と、**全体ビューはシートごと**。
- **A・B列（名簿）と、予備の行の記入欄（L〜N列）にはあえて掛けていない。**
  正しい操作にまで警告を出すと、やがて中身を読まずに［OK］を押すようになる。
- 目印は `EDIT_GUARD_TAG`。この文字列で始まる保護だけを触るので、
  学校側が自分で付けた保護には影響しない。すでにあれば作り直さない。

**2. すり抜けたら必ず記録に残す**

- `onEdit` は、書いた瞬間に人が触ったことが確実に分かる唯一の場所。ここで
  予約ログへ `未登録の手入力`（`STRAY_EDIT_ACTION`）として残す。
- 全体ビューへの書き込みも対象にした（これまで警告すら出ていなかった）。
- 🩺データ点検（`checkStrayEdits_`）で過去14日ぶんをクラスごとに出す。
  受付開始前の点検も `checkData()` を通るので、そこにも出る。
- **作り直しの側（`captureReserveEntries_`）では検知していない。**
  あの処理は「表が古いだけ」と「担任が書いた」を区別できない
  （保護者が予約するたびに表は古くなるので、そこで拾うと誤検知だらけになる）。

**3. 予備への手入力にも、管理画面と同じ確認を通した**

- これまで `captureReserveEntries_()` は手入力を素通しで取り込んでいた。
  名簿に無い名前をそのまま枠マスタへ書けたし、すでに面談が入っている生徒を
  予備にも入れられた（当日の受付一覧に二重に並ぶ）。
  管理画面や小窓からは両方とも弾いているのに、手入力だけ穴だった。
- 名簿との照合と二重予約の確認を通し、通らなければ取り込まずに
  `未登録の手入力` として記録し、その場でもトーストで知らせる。
- 取り込めなかった内容は次の作り直しで元に戻る（＝入力は無かったことになる）。

- 変更ファイル: `Config.js` `Slots.js` `Admin.js` `Check.js`
- **再デプロイは不要**（保護者・担任のウェブ画面は触っていない）。
- 反映は、次に `全体ビュー・予約表を更新` が走ったときから。保護もそのときに付く。

### v4.6.13（2026-09-03）予備の枠へシートから入れられるようにし、消える不具合を直した

- シートのメニュー「選んだ行を操作 ▸ この枠に生徒を入れる」で予備の行を選ぶと、
  「予備の枠です。黄色い（予備）の行に直接ご記入ください。」で弾かれていた。
  予備コマは v4.6.0 で足した機能なので、それ以前は全部が通常の枠で、この小窓から入れられていた。
  予備の枠なら、Web管理画面の黄色いセルを押したときと同じ記入として扱うようにした。
  予備は保護者に見えない枠なので、予約コードは発行しない（小窓の文面もそれに合わせた）。
- **あわせて、予備に入れた生徒が消える不具合を直した。**
  `captureReserveEntries_()` は、予備の行だけ「予約表_〇組」の内容を担任の手入力とみなして
  枠マスタへ書き戻す。枠マスタにだけ書いた直後は予約表がまだ空なので、
  次の表の作り直しでその空の内容が枠マスタへ戻され、入れた生徒が消えていた。
  **Web管理画面から予備に入れた場合も同じで、5分おきの表示更新で黙って消えていた。**
  記入と同時に「予約表_〇組」の該当行へも書き写すことで、どちらの経路でも残るようにした。
- 予備への記入・消去の処理は Web管理画面とシートで1つ（`setReserveStudent_`）にまとめた。
  予約ログの「詳細」で、どちらから操作したか（担任Web／担任シート）が分かる。
- 変更ファイル: `Config.js` `Admin.js` `assign.html`
- **再デプロイは不要。** `assign.html` はシートのメニューから `showModalDialog` で開く小窓で、
  ウェブアプリの `doGet` を通らない。保護者・担任の画面（`index.html` / `admin.html`）は
  触っていないので、`clasp push` だけで両方のスクリプトに反映される。

### v4.6.8（2026-09-03）Androidで読めないQRコードを修正

- QR規格の「形式情報」15ビットが、縦・横とも規格と異なる順番で配置されていた。
  iPadの読み取りでは通る場合があったが、Androidで広く使われるZXing系では復号できなかった。
- `QrCode.js` の `qrApplyFormat_()` をJIS X 0510 / ISO/IEC 18004の配置順に修正。
- 形式情報の誤りを回避するために入っていた「マスク2を使わない」特例も削除。
  これにより規格どおり8種類から最適なマスクを選ぶ。
- 2つの本番候補URL、8種類すべてのマスク（計16パターン）を標準QRライブラリと照合し、不一致0マスを確認。
- 実際に選ばれるQRをZXingで復号し、2URLとも元のURLへ完全一致することを確認。
- 変更ファイル: `Config.js` `QrCode.js`

**運用前に足した4件**（2026-08-22 push 済み・v4.4.0）

1. **受付開始前の自動点検** — `受付を開始する` が、押した時点で `checkData()` を走らせ、
   さらに **保護者用URLに実際にアクセスして200が返るか**を確かめる（`parentUrlReachability_`）。
   `UrlFetchApp` はブラウザのログイン情報を持たないので、保護者と同じ条件で試せる。
   302/401/403 なら「ログインを求められます」として止める。デプロイ設定の間違いはここで出る。
   エラーがあっても最終的には続行を選べる（止めるのではなく、気づかせる）。
2. **受付期間中の自動バックアップ** — `準備・メンテナンス ▸ 📦 毎日の自動バックアップを設定する`。
   毎日2時に走り、**公開中かつ締切前のときだけ**バックアップを取る。停止中・締切後は素通りするので
   ファイルは増え続けない。実行すると `予約ログ` に「自動バックアップ」として残る。
3. **当日の受付一覧（全校・時間順）** — `📄 印刷用PDFを作る` に追加。日付 → 時間 → クラスの順で、
   来校する家庭だけを並べる。受付本部の1枚用。クラス別の予約表は担任の手元用なので別物。
4. **保護者の完了画面に控えの取り方** — 「この画面のスクリーンショットを撮っておくと確実です」。
   メールを集めない方針なので、予約コードを控え損ねると保護者は自力で確認できない。
   1人予約・きょうだい予約の両方の完了画面に入れた。

**4は `index.html` なので再デプロイが必要だった。2026-08-23 のバージョン20で配信を確認済み。**

原本へは `-P` で設定ファイルを指定する。

```

clasp push --force -P 'C:\OBS\Myobs\37_三者面談\.clasp.production.json'
```

相対パスやスラッシュ区切りだと、clasp 3.4.1 が
`Security Error: srcDir … escapes project root` で止まる（パスの表記が食い違うため）。
`.clasp.production.json` に `rootDir` は書かない（同じエラーになる）。
